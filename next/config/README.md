# Shipped configurations

Every host reaches the daemon through `tsm-relay` over stdio. The first relay (or `tsm`) that finds no daemon starts one, so none of these needs a supervisor. The units start the daemon again after a crash, and keep it across logins only where the user's service manager outlives a logout, which on Linux takes lingering (`loginctl enable-linger`); on macOS a launch agent stops at logout. `--scope` names the sessions a host sees: two hosts with different scopes never share a `main`.

| File | For |
|---|---|
| `agent-framework.recipe.json` + `agent-framework.gate.json` | connectome agents: the `mcplServers` entry for a recipe (replace `AGENT` with the agent's name, so each agent has its own scope) and the policy to merge into the agent's `_config/gate.json`, above its broad defer rules (first match wins). It enables `terminal.tools` and `terminal.events`, so a command that ends after its call returned, a program waiting for input, a shell that exits and a pattern the agent asked for wake the agent, and nothing else does. An end, a wait for input or an exit wakes the agent only when no call of the agent's has returned it: a `run` still waiting when its program starts reading input returns that itself, and no wake follows. A pattern wakes it once, when the session finds it after the call that asked for it has returned, whether or not a call has shown that line; a match `run` finds within its own wait comes in its result, and no wake follows. `reconnect: true` starts a new relay when the daemon goes away; the relay itself never reconnects. |
| `mcpl-bridge.json` | Claude Code through `mcpl-cc-bridge`: merge the `terminal` entry into your bridge config (`$CLAUDE_PROJECT_DIR/.mcpl-bridge.json` or `~/.claude/mcpl-bridge/config.json`). The same two feature sets and the same four wakes. Allow the tools with one permission entry: `mcp__plugin_mcpl-bridge_mcpl__terminal__*`. Its scope is `claude`, so every Claude Code window using it shares one set of sessions and their wakes; give a window its own `--scope` in a project's config to keep its shells apart. |
| `mcp.json` | Plain MCP hosts (Cursor, Claude Desktop, Claude Code without the bridge). They get the nine tools and no wakes: `look` with `until` is how they wait. Its scope is `default`, the one `tsm` uses when given none, so every host using it shares one set of sessions with the others and with `tsm`; give a host its own `--scope` to keep its shells apart. |
| `termd.service`, `com.animalabs.termd.plist`, `termd-launch.sh` | Supervising the daemon with systemd or launchd. Both run `termd-launch.sh`, which finds node where Homebrew, Volta or nvm put it (nvm's default version, as `nvm use` would pick it; a supervisor's PATH has none of them), or the one `TSM_NODE_BIN` names, puts those directories on PATH and starts in `$HOME`. Replace the `PACKAGE` placeholder, and in the plist `/Users/YOU` with your home directory. Write `&` as `&amp;` and `<` as `&lt;` in the plist, and `%` as `%%` in the unit. Both give the daemon 20 s from SIGTERM to SIGKILL, the time its stop gives every session's close. A plist without `ExitTimeOut` gets launchd's default, which was 5 s on GitHub's macOS 15 and 26 runners, and a close can then be cut off. |

The daemon's socket is `$XDG_RUNTIME_DIR/terminal-sessions/daemon.sock`; where that variable isn't set, `/run/user/<uid>/terminal-sessions/daemon.sock` on Linux when that directory is yours alone; otherwise `/tmp/terminal-sessions-<uid>/daemon.sock`. Each is in a directory only you can enter; `--socket` on `termd`, `tsm-relay` and `tsm` names another. A remote machine is reached by running the relay there over ssh, as [Another machine, over ssh](../README.md#another-machine-over-ssh) describes.
